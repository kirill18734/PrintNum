# PrintNum Backend

Локальный HTTP-сервис для печати этикеток, номеров и полок Ozon в Windows. Backend принимает HTTP-запросы от интерфейса приложения и других локальных клиентов, обрабатывает текст с учётом настроек и отправляет задания на выбранный принтер Windows.

## Возможности

- Печать ячеек, текста и изображения штрихкодов, QR-кодов и Data Matrix с учётом пользовательских настроек.
- Пропуск автоматической печати для ячеек, указанных в `excludedTexts`.
- Переименование Ozon Полки.
- Получение списка доступных принтеров Windows.
- Проверка готовности выбранного принтера.
- Кеширование конфигурации и состояния принтера для сокращения количества обращений к Windows API.
- Последовательная обработка заданий печати для предотвращения одновременного обращения к принтеру из нескольких обработчиков.
- Автоматическое завершение процесса при простое в обычном режиме запуска.

## Архитектура

Backend построен на Flask. Архитектура разделена на точку входа и несколько модулей с конкретными задачами.

```text
HTTP-клиенты
     |
     v
backend.py
     |
     +---- HTTP-маршруты
     |
     +---- Состояние принтера
     |       printerOnline
     |
     +---- app/data.py
     |       Конфигурация
     |
     +---- app/auto_print.py
     |       Автоматическая печать
     |
     +---- app/label_print.py
     |       Создание этикеток

             Общие операции печати
                    |
                    v
               Windows API
                    |
                    v
              Принтер Windows
```

### Основные принципы

**Единая точка входа.** Файл `backend.py` запускает HTTP-сервер и содержит обработчики запросов.

**Разделение по назначению.** Логика печати, конфигурация и вспомогательные функции вынесены в отдельные модули папки `app/`.

**Кеширование статуса принтера.** Переменная `printerOnline` хранит последнее известное состояние выбранного принтера. В обычном режиме она обновляется обработчиком `/status-printer`, что позволяет не проверять состояние принтера при каждом запросе.

**Последовательная печать.** Блокировка `_print_lock` защищает участок отправки заданий от одновременного выполнения несколькими обработчиками.

**Без лишних уровней абстракции.** Проект не использует отдельные слои API, сервисов, домена, инфраструктуры и фабрику приложения. Для небольшого проекта, который поддерживает один разработчик, модули сгруппированы по практическим задачам.

## Структура проекта

```text
PrintNum/
├── backend.py              # Точка входа, HTTP API, состояние сервера
├── config.json             # Локальная конфигурация, если используется
└── app/
    ├── __init__.py         # Пакет приложения
    ├── data.py             # Загрузка и кеширование настроек
    ├── utils.py            # Вспомогательные функции
    ├── auto_print.py       # Автоматическая печать номеров
    └── label_print.py      # Ручная печать этикеток
```

### Назначение файлов

| Файл                 | Ответственность                                                |
| -------------------- | -------------------------------------------------------------- |
| `backend.py`         | Запуск сервера, HTTP-маршруты, состояние принтера и блокировки |
| `app/data.py`        | Чтение конфигурации, кеширование и обработка ошибок чтения     |
| `app/utils.py`       | Общие вспомогательные функции                                  |
| `app/auto_print.py`  | Форматирование и печать номеров, обработка исключений          |
| `app/label_print.py` | Подготовка и печать текстовых этикеток и изображений кодов     |

При изменении алгоритмов печати следует редактировать соответствующий модуль, не перенося всю логику в `backend.py`.

## Требования

- Windows 10 или Windows 11.
- Python 3.10 или новее.
- Установленный и настроенный принтер Windows.
- Драйвер принтера, поддерживающий печать через Windows API.
- Зависимости Python, перечисленные в `requirements.txt`.

Фактическая отправка заданий на печать использует Windows API через `pywin32` и обработку изображений через Pillow.

## Установка

Откройте терминал в корне проекта.

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Перед запуском убедитесь, что выбранный принтер установлен в Windows и доступен для печати.

## Конфигурация

Backend читает пользовательские настройки из конфигурационного JSON-файла. Основной путь для совместной работы с приложением — `%APPDATA%\PrintNum\config.json`. Если данный файл не найден, то ищется в корневой папке

```text
PrintNum/
├── backend.py              # Точка входа, HTTP API, состояние сервера
├── config.json             # Локальная конфигурация
└── app/...
```

Конфигурация предназначена для чтения backend: настройки изменяются на стороне приложения, а backend загружает их и кеширует. При изменении файла кеш обновляется по времени модификации.

### Основные параметры

| Параметр        | Тип       | Назначение                                                       |
| --------------- | --------- | ---------------------------------------------------------------- |
| `printer`       | `string`  | Имя выбранного принтера Windows                                  |
| `excludedTexts` | `array`   | Фразы, при наличии которых автоматическая печать пропускается    |
| `paper`         | `string`  | Размер этикетки в миллиметрах, например `30*20`                  |
| `idNum`         | `boolean` | Настройка печати дополнительной части номера                     |
| `endLine`       | `boolean` | Настройка завершающего оформления номера                         |
| `hybrid`        | `boolean` | Включение гибридного форматирования                              |
| `expand`        | `number`  | Порог, используемый гибридным форматированием                    |
| `themeStyle`    | `string`  | Стиль оформления, если он поддерживается текущей конфигурацией   |
| `bold`          | `boolean` | Настройка жирного начертания, если применима к выбранному режиму |
| `theme`         | `string`  | Тема оформления, если применима к выбранному режиму              |

Пример конфигурации:

```json
{
  "paper": "30*20",
  "endLine": false,
  "hybrid": true,
  "expand": 500,
  "themeStyle": "vercel",
  "bold": false,
  "printer": "CHITENG-CT221B",
  "excludedTexts": [
    "Прямой поток",
    "Расходники",
    "Возврат",
    "Продавцу",
    "Ozon Полка"
  ],
  "theme": "dark",
  "idNum": false
}
```

### Правила исключений

`excludedTexts` содержит фразы, при совпадении с которыми автоматическая печать пропускается.

- Сравнение выполняется без учёта регистра.
- Проверяется наличие фразы внутри входного текста.
- Совпадение не требует полного равенства строк.

Например, при наличии правила `Ozon Полка` запрос с текстом `Ozon Полка - 1` соответствует исключению и не должен отправляться на печать.

Важно использовать именно ключ `excludedTexts`, поскольку он соответствует формату конфигурации.

## Запуск и остановка

### Обычный режим

Запустите сервер из корня проекта:

```powershell
python backend.py
```

Backend слушает локальный адрес:

```text
http://127.0.0.1:5000
```

В обычном режиме используется кешированное состояние принтера. Оно обновляется при обращении к `/status-printer`.

Если сервер не получает запросов в течение установленного времени простоя, он может завершить работу. Текущее значение тайм-аута и поведение завершения определяются реализацией в `backend.py`. По умолчанию тайм-аут простоя = 10 сек.

### Автономный режим

Для запуска без автоматического завершения по тайм-ауту простоя используйте:

```powershell
python backend.py --standalone
```

В этом режиме сервер продолжает работать без запросов от интерфейса. Перед обработкой печати через `/print-number` и `/ozon-shelf` выполняется проверка текущего состояния выбранного принтера, а кеш обновляется по результату проверки.

Если принтер недоступен или проверка завершается ошибкой, задание не должно отправляться на печать.

### Остановка

Остановка выполняется предусмотренным текущей реализацией механизмом завершения процесса. Если backend запущен как дочерний процесс десктопного приложения, то при любых сценариях он завершиться либо по запросу из интерфейса или по тайм-ауту простоя (10 сек). Если backend запущен с аргументом `--standalone` , то завершение реализовывается вручную по запросу пользователя

## HTTP API

Базовый адрес:

```text
http://127.0.0.1:5000
```

Для POST-запросов с JSON используйте заголовок:

```http
Content-Type: application/json
```

### `GET /`

Проверка доступности backend.

Пример ответа:

```json
{
  "status": true
}
```

### `GET /listPrinters`

Возвращает список принтеров, доступных через Windows.

Пример ответа:

```json
{
  "listPrinters": ["CHITENG-CT221B"]
}
```

### `GET /status-printer`

Проверяет состояние выбранного принтера и обновляет глобальную переменную `printerOnline`.

Пример ответа:

```json
{
  "printerOnline": true
}
```

Значение `true` означает, что проверка определила принтер как доступный. Оно не гарантирует, что физическая печать каждого задания обязательно завершится успешно.

В обычном режиме перед отправкой заданий учитывается последнее известное состояние. Поэтому клиенту следует вызывать `/status-printer`, когда требуется обновить статус перед последующими запросами на печать.

### `POST /print-number`

Автоматическая печать номера или текста с учётом настроек и правил исключений.

Пример запроса:

```json
{
  "text": "500-1"
}
```

Возможные результаты:

- Успех — запрос обработан, задание передано в существующую логику печати.
- Пропуск — текст соответствует правилу исключения.
- Ошибка запроса — отсутствуют или некорректны необходимые данные.
- Ошибка печати — возникла проблема при подготовке или отправке задания.

Формат номера зависит от параметров `idNum`, `endLine`, `hybrid` и `expand`.

### `POST /ozon-shelf`

Принимает текст полки Ozon и передаёт его в логику обработки для печати.

Пример запроса:

```json
{
  "text": "Ozon Полка - 1"
}
```

Применяются проверки, предусмотренные обработчиком и логикой автоматической печати, включая правила исключений.

### `POST /print-label`

Ручная печать этикетки.

Пример запроса для текстовой этикетки:

```json
{
  "contentType": "text",
  "content": "Заказ № 12345",
  "bold": false,
  "underline": false,
  "showCodeText": false
}
```

Поддерживаемые типы содержимого:

| `contentType` | Назначение         |
| ------------- | ------------------ |
| `text`        | Печать текста      |
| `barcode`     | Печать штрихкода   |
| `qr`          | Печать QR-кода     |
| `datamatrix`  | Печать Data Matrix |

Для графических кодов требуется изображение PNG, переданное в Base64 через поле `codeImage`. Поле `content` используется для содержимого этикетки.

Пример успешного ответа:

```json
{
  "status": "printed"
}
```

## Обработка запросов на печать

### Последовательная отправка заданий

Для защиты принтера от одновременной отправки заданий используется блокировка `_print_lock`.

Она сериализует выполнение защищённого участка кода, но не объединяет несколько HTTP-запросов в очередь с гарантированной доставкой и не гарантирует физическую печать каждого принятого запроса.

Если два запроса поступают одновременно, результат зависит также от проверок, исключений и ошибок, возникающих в обработчиках. Для диагностики следует проверять журналы обоих запросов и их HTTP-ответы.

### Состояние принтера

Переменная `printerOnline` хранит последнее известное состояние принтера.

- `/status-printer` обновляет состояние.
- В обычном режиме обработчики, использующие кеш, ориентируются на последнее сохранённое значение.
- В автономном режиме для `/print-number` и `/ozon-shelf` предусмотрена повторная проверка перед печатью.

Если состояние принтера не обновлено, кеш может не отражать его текущее состояние. Для проверки доступности следует вызвать `/status-printer`.

### Подготовка печати

Автоматическая печать и ручная печать этикеток реализованы отдельно.

Изменения в алгоритмах подбора шрифта и форматирования следует выполнять только при необходимости, проверяя результат на используемом принтере и выбранном размере бумаги.

## Обработка ошибок

При диагностике ориентируйтесь на фактический HTTP-код и JSON-ответ, полученный от конкретного маршрута. Точные коды ошибок могут различаться между обработчиками.

Типовые причины неудачной печати:

- Не выбран принтер в конфигурации.
- Принтер выключен, отключён или не готов к печати.
- Входной JSON не содержит обязательных полей.
- Для графического кода переданы некорректные данные или изображение.
- Возникла ошибка Windows API, драйвера или отправки задания.
- Текст совпал с правилом исключения и был намеренно пропущен.

Пропуск по правилу исключения не является ошибкой принтера.

## Диагностика

Если печать не выполняется:

1. Убедитесь, что backend запущен и отвечает на `GET /`.
2. Проверьте список доступных принтеров через `GET /listPrinters`.
3. Убедитесь, что в конфигурации выбран правильный принтер.
4. Вызовите `GET /status-printer` и проверьте `printerOnline`.
5. Проверьте `excludedTexts` на наличие совпадающей фразы.
6. Проверьте тело запроса и HTTP-ответ.
7. Изучите сообщения backend в консоли, особенно при одновременных запросах.

При проблемах с двумя одновременными запросами проверьте, получили ли обработчики оба запроса, какой из них первым вошёл в участок печати, не был ли один запрос пропущен по исключению и не завершился ли он ошибкой до отправки задания.
