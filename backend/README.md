# PrintNum Backend

Локальный HTTP-сервис для автоматизированной и ручной печати этикеток Ozon в операционной системе Windows. Сервер принимает HTTP-запросы от клиентских приложений (интерфейса десктопного приложения или других локальных потребителей), обрабатывает входящие текстовые данные и графические коды в соответствии с конфигурацией и последовательно отправляет задания на печать через Windows API.

## Возможности

- **Различные типы этикеток:** Печать номеров ячеек, произвольного текста, а также генерация и печать штрихкодов, QR-кодов и Data Matrix.
- **Фильтрация трафика (Исключения):** Пропуск автоматической печати для документов и ячеек, содержащих маркеры из списка `excludedTexts`.
- **Интеграция с Ozon:** Специализированная обработка и переименование Ozon Полок.
- **Взаимодействие с ОС:** Получение актуального списка установленных в Windows принтеров и низкоуровневая проверка их готовности.
- **Оптимизация производительности:** Кеширование конфигурационных файлов и текущего состояния принтера для минимизации накладных расходов на обращения к Windows API.
- **Потокобезопасность:** Последовательная обработка заданий печати с использованием потоковых блокировок для предотвращения конфликтов в спулере печати (Print Spooler).
- **Энергосбережение:** Автоматическое завершение процесса при длительном простое в стандартном режиме работы.

## Архитектура и компоненты

Проект реализован на базе микрофреймворка Flask. Точкой входа является файл `backend.py`, координирующий работу модулей ядра, вынесенных в директорию `app/`.

```text
HTTP-клиенты (UI / Локальная сеть)
     |
     v
backend.py (Точка входа)
     |
     +---- HTTP-маршруты & Контроллеры
     |
     +---- Состояние (Глобальный кеш: printerOnline, Блокировка: _print_lock)
     |
     +---- app/data.py (I/O операции, валидация и кеширование config.json)
     |
     +---- app/auto_print.py (Бизнес-логика, форматирование и печать номеров/ячеек)
     |
     +---- app/label_print.py (Рендеринг этикеток: текст, генерация и отрисовка кодов)
     |
     +---- app/utils.py (Вспомогательные функции)
             |
             v
        Windows API (через pywin32 и Pillow)
             |
             v
       Принтер Windows
```

### Архитектурные принципы

1. **Единая точка входа:** `backend.py` инициализирует Flask-приложение, настраивает политики маршрутизации, управляет жизненным циклом процесса и разделением ресурсов.
2. **Низкая связанность модулей:** Вся логика генерации изображений, подбора шрифтов и работы с графикой инкапсулирована в `app/auto_print.py` и `app/label_print.py`. Компоненты не влияют на работу друг друга.
3. **Кеширование состояния (State Caching):** Глобальная переменная `printerOnline` снижает количество ресурсоемких вызовов функций Windows API. Состояние обновляется асинхронно или по требованию через специализированный эндпоинт.
4. **Синхронизация доступа к оборудованию:** Глобальный мьютекс `_print_lock` защищает критическую секцию отправки данных в спулер Windows, выстраивая конкурентные HTTP-запросы в последовательную очередь на уровне потоков Flask.

### Назначение файлов ядра

| Компонент            | Зона ответственности                                                                                                             |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| `backend.py`         | Маршрутизация HTTP, управление конкурентностью (`_print_lock`), менеджмент жизненного цикла сервера.                             |
| `app/data.py`        | Мониторинг времени модификации (mtime) `config.json`, чтение, парсинг и потокобезопасное кеширование настроек.                   |
| `app/utils.py`       | Разделяемые утилиты, не содержащие специфичной бизнес-логики печати.                                                             |
| `app/auto_print.py`  | Парсинг Ozon-номеров, применение гибридного форматирования, расчет геометрии этикеток под размеры бумаги.                        |
| `app/label_print.py` | Декодирование Base64 графических кодов, генерация растровых изображений (Pillow) и отправка сырых графических данных на принтер. |

## Системные требования

- **ОС:** Windows 10 / Windows 11 (64-bit).
- **Среда выполнения:** Python 3.10 или новее.
- **Оборудование:** Установленный в системе принтер этикеток с драйвером, поддерживающим стандартную подсистему печати Windows (GDI/WinSpool).
- **Ключевые зависимости:** `pywin32` (интерфейс к подсистеме Windows), `Pillow` (обработка графики), `Flask` (HTTP-сервер). Полный список зафиксирован в `requirements.txt`.

## Конфигурация

Конфигурационный файл `config.json` является общим ресурсом для Backend и управляющего десктопного интерфейса. Изменения вносятся интерфейсом, Backend работает в режиме **Read-Only**.

**Стратегия поиска конфигурации:**

1. Проверяется путь в системной директории пользователя: `%APPDATA%\PrintNum\config.json`.
2. Если файл отсутствует, используется локальный `config.json` из корневой директории исполнения Backend.

### Параметры конфигурации

| Ключ            | Тип              | Назначение                                                           |
| :-------------- | :--------------- | :------------------------------------------------------------------- |
| `printer`       | `string`         | Точное имя принтера в подсистеме печати Windows.                     |
| `paper`         | `string`         | Габариты ленты в мм в формате `Ширина*Высота` (например, `"30*20"`). |
| `excludedTexts` | `array [string]` | Массив строк-маркеров. При их обнаружении автопечать отменяется.     |
| `idNum`         | `boolean`        | Флаг печати дополнительного идентификатора номера.                   |
| `endLine`       | `boolean`        | Флаг отрисовки завершающей декоративной линии.                       |
| `hybrid`        | `boolean`        | Переключатель режима гибридного форматирования текста.               |
| `expand`        | `number`         | Числовой порог-триггер для алгоритмов гибридного форматирования.     |
| `themeStyle`    | `string`         | Идентификатор визуального стиля компоновки элементов этикетки.       |
| `theme`         | `string`         | Цветовая или стилистическая схема оформления (`"dark"`, `"light"`).  |
| `bold`          | `boolean`        | Глобальный флаг использования жирного начертания шрифтов.            |

### Пример валидного `config.json`

```json
{
  "printer": "CHITENG-CT221B",
  "paper": "30*20",
  "excludedTexts": [
    "Прямой поток",
    "Расходники",
    "Возврат",
    "Продавцу",
    "Ozon Полка"
  ],
  "idNum": false,
  "endLine": false,
  "hybrid": true,
  "expand": 500,
  "themeStyle": "vercel",
  "theme": "dark",
  "bold": false
}
```

### Алгоритм фильтрации по `excludedTexts`

Перед отправкой задания на маршруты автопечати текст проверяется по правилам исключений:

- Проверка выполняется по принципу `substring` (вхождение подстроки в строку).
- Регистр символов **игнорируется** (приведение к нижнему регистру перед сравнением).
- Полного совпадения строк не требуется. Строка `"Ozon Полка - 1"` будет отфильтрована правилом `"Ozon Полка"`.

## Режимы запуска и управление процессом

### Стандартный режим (Управляемый)

Запускается командной:

```powershell
python backend.py
```

- Предназначен для работы в качестве дочернего процесса основного десктопного приложения.
- **Тайм-аут простоя:** Если в течение **10 секунд** сервер не получает ни одного HTTP-запроса, процесс автоматически завершает свою работу для освобождения системных ресурсов.
- Использует кешированное состояние принтера из `printerOnline`.

### Автономный режим (Standalone)

Запускается с флагом:

```powershell
python backend.py --standalone
```

- Сервер работает перманентно и не завершает процесс по тайм-ауту простоя.
- **Остановка процесса:** Выполняется пользователем вручную через прерывание в консоли (`Ctrl+C`) или средствами ОС (сигналы завершения процесса/`taskkill`).
- **Строгая проверка:** Перед каждой операцией на эндпоинтах `/print-number` и `/ozon-shelf` сервер инициирует принудительный опрос состояния принтера через Windows API, минуя кеш. Если принтер не отвечает, запрос отклоняется с ошибкой.

## HTTP API

Базовый URL сервиса: http://127.0.0.1:5000. Все POST-запросы требуют обязательного заголовка Content-Type: application/json. Сервис всегда возвращает ответы в формате JSON. 

### GET /

Проверка доступности и работоспособности сервиса (Heartbeat). 

- **Код ответа:** 200 OK
- **Пример ответа:** 

```json
{
  "status": true
}
```

### GET /listPrinters

Получение списка всех установленных в операционной системе Windows принтеров. 

- **Код ответа:** 200 OK
- **Пример ответа:** 

```json
{
  "listPrinters": [
    "CHITENG-CT221B",
    "XPrinter XP-365B",
    "Microsoft Print to PDF"
  ]
}
```

### GET /status-printer

Принудительный опрос состояния выбранного принтера (из ключа printer в конфигурации) через Windows API и обновление глобальной переменной кеша printerOnline. 

- **Код ответа:** 200 OK
- **Пример ответа:** 

```json
{
  "printerOnline": true
}
```

**Важно:** Возврат значения true указывает на то, что принтер успешно инициализирован в ОС и его драйвер готов принимать задачи. Это логическая готовность подсистемы Windows, которая не гарантирует отсутствие аппаратных проблем (отсутствие бумаги, открытая крышка) непосредственно в момент протяжки ленты. В обычном режиме работы клиенту рекомендуется вызывать этот эндпоинт перед отправкой пула задач, чтобы актуализировать кеш. 

### POST /print-number

Автоматизированная печать номера ячейки или произвольного текста с парсингом параметров и применением правил фильтрации из excludedTexts. 

- **Тело запроса:** 

```json
{
  "text": "500-1"
}
```

- **Возможные сценарии ответов:** 
  - **Успешная постановка в очередь (200 OK):** {"status": "printed"}
  - **Пропуск по правилу исключения (200 OK):** {"status": "skipped", "reason": "Text matched excluded rule"}
  - **Ошибка валидации данных (400 Bad Request):** {"status": "error", "message": "Missing required 'text' field"}
  - **Ошибка печати / Принтер недоступен (500 Internal Server Error):** {"status": "error", "message": "Windows API Error: Printer is offline"}

### POST /ozon-shelf

Специализированный эндпоинт для обработки и автоматической печати наименований полок Ozon. К нему в полном объеме применяются логика парсинга, гибридного форматирования и правила фильтрации excludedTexts. 

- **Тело запроса:** 

```json
{
  "text": "Ozon Полка - 1"
}
```

- **Возможные сценарии ответов:** Полностью идентичны маршруту /print-number (включая обработку пропусков skipped и ошибок).

### POST /print-label

Ручная (прямая) печать этикеток с возможностью передачи произвольного текста или готовой графики в обход автоматических фильтров исключений. 

- **Поддерживаемые типы содержимого (contentType):** 
  - "text" — прямая печать текстового блока.
  - "barcode" — линейный штрихкод.
  - "qr" — QR-код.
  - "datamatrix" — 2D-код Data Matrix.

- **Пример запроса для текстовой этикетки:** 

```json
{
  "contentType": "text",
  "content": "Заказ № 12345",
  "bold": false,
  "underline": false,
  "showCodeText": false
}
```

- **Пример запроса для графического кода (barcode, qr, datamatrix):**
  Сгенерированное на стороне клиента изображение передается в виде сырой строки Base64 в поле codeImage. Поле content может использоваться для сопутствующей текстовой подписи. 

```json
{
  "contentType": "qr",
  "content": "Данные внутри QR",
  "codeImage": "iVBORw0KGgoAAAANSUhEUgAA...",
  "bold": false,
  "underline": false,
  "showCodeText": true
}
```

- **Возможные сценарии ответов:** 
  - **Успешная печать (200 OK):** {"status": "printed"}
  - **Ошибка кодирования / Валидации (400 Bad Request):** {"status": "error", "message": "Invalid Base64 data in 'codeImage'"}
  - **Сбой подсистемы печати Windows (500 Internal Server Error):** {"status": "error", "message": "Win32 Print Spooler error"}

### Логика обработки запросов и отказоустойчивость

### Конкурентность и потокобезопасность (Мьютекс)

Микрофреймворк Flask по умолчанию обрабатывает входящие HTTP-запросы асинхронно в многопоточном режиме. Для предотвращения состояния гонки (Race Condition) и одновременного обращения к одному физическому принтеру из разных потоков внедрен следующий механизм: 

- Критический участок кода внутри модулей app/auto_print.py и app/label_print.py, отвечающий за открытие дескриптора принтера (OpenPrinter) и отправку данных (StartDocPrinter/WritePrinter), защищен глобальной потоковой блокировкой \_print_lock.
- При одновременном поступлении нескольких запросов на печать от разных клиентов, потоки Flask выстраиваются в очередь ожидания освобождения мьютекса.
- Данный механизм сериализует отправку байтов в спулер Windows, исключая смешивание или порчу графического контекста разных этикеток.
- **Ограничение:** Очередь существует исключительно в оперативной памяти текущего процесса. Сервис не является персистентным брокером сообщений. При перезапуске или аварийном завершении бэкенда недоставленная очередь запросов стирается.

### Стратегия изоляции ошибок

Бэкенд строго разграничивает типы возникающих сбоев для обеспечения предсказуемого поведения вызывающего интерфейса: 

1. **Логические пропуски (Бизнес-логика):** Совпадение текста с фильтрами excludedTexts намеренно **не генерирует HTTP-ошибку**. Сервис возвращает код 200 OK со статусом "skipped". Это позволяет фронтенду или вызывающему скрипту продолжать потоковую обработку без прерывания цепочки выполнения.
2. **Сбои валидации (400 Bad Request):** Возникают до захвата блокировки \_print_lock. Ошибки парсинга JSON, пустые поля или невалидный формат Base64 отсекаются сразу, сохраняя ресурсы процессора.
3. **Аппаратные и системные сбои (500 Internal Server Error):** Ошибки обрыва связи с принтером, сбои отрисовки холста Pillow или отказы драйвера Windows перехватываются глобальным обработчиком. Блокировка \_print_lock гарантированно освобождается в блоке finally, предотвращая мертвую блокировку (Deadlock) сервера.

### Диагностика и устранение неполадок

Если бэкенд возвращает ошибки или запросы проходят со статусом "printed", но принтер не выдает ленту, выполните диагностику по следующим шагам: 

1. **Проверка сетевого слоя:** Выполните запрос GET http://127.0.0.1:5000/. Если ответ отсутствует, убедитесь, что процесс python backend.py активен, порт 5000 не занят другим приложением, а локальный брандмауэр не блокирует Loopback-интерфейс.
2. **Верификация идентификатора устройства:** Сравните список из GET /listPrinters со значением ключа "printer" в вашем файле config.json. Имена должны совпадать **символ в символ**, включая регистр, пробелы и спецсимволы.
3. **Проверка низкоуровневой связи:** Вызовите GET /status-printer. Если возвращается false: 

- Проверьте физическое подключение кабеля USB/Ethernet к принтеру и наличие питания.
- Откройте штатную утилиту «Просмотр очереди печати» в Windows и убедитесь, что принтер не переведен в режим «Работать автономно» и в очереди нет зависших или поврежденных документов (очистите очередь при необходимости).

4. **Анализ логов фильтрации:** Если эндпоинт возвращает статус "skipped", выведите текущее содержимое config.json и проверьте массив excludedTexts. Помните, что фильтр ищет частичное вхождение подстроки без учета регистра.
5. **Тестирование Base64-графики:** При отправке этикеток через /print-label убедитесь, что строка в codeImage является чистым Base64-кодом. Присутствие URI-префиксов (например, data:image/png;base64,) вызовет ошибку декодирования в Pillow.
6. **Анализ конкурентных запросов:** При массовой одновременной отправке заданий изучите консольный вывод сервера. Если один из запросов завершается с ошибкой 500 до входа в критическую секцию печати, проверьте время ожидания потока на блокировке \_print_lock и таймауты на стороне клиента.
