# PrintNum Backend

Локальный HTTP-сервис для автоматической и ручной печати этикеток в Windows. Backend принимает запросы от десктопного интерфейса и других локальных клиентов, подготавливает содержимое этикеток и отправляет задания в Windows Print Spooler через GDI/Win32 API.

## Возможности

- Автоматическая печать номеров и текстов через `/print-number` и `/ozon-shelf`.
- Ручная печать текстовых этикеток, штрихкодов, QR-кодов и Data Matrix через `/print-label`.
- Фильтрация автоматических заданий по списку `excludedTexts`.
- Применение отдельных настроек шрифтов и фонов для автоматической и ручной текстовой печати.
- Фоновое обновление состояния выбранного принтера и списка доступных принтеров.
- История последних 100 автоматических текстовых заданий, доступная одним запросом `/printer-data`.
- Очистка Windows Print Queue перед каждым автоматическим заданием. Ошибки очистки журналируются и не блокируют отправку задания на печать.
- Последовательная отправка заданий на печать с помощью общей блокировки.
- Автоматическое завершение процесса после периода бездействия в стандартном режиме.

## Архитектура и компоненты

Проект использует Flask. Точка входа — `backend.py`; остальные модули находятся в директории `app/`.

```text
HTTP-клиенты
    |
    v
backend.py
    |
    +-- HTTP-маршруты и состояние приложения
    +-- Мониторинг принтера и списка принтеров
    +-- _print_lock: последовательная отправка заданий
    |
    +-- app/config.py
    |      Чтение и кеширование config.json
    |
    +-- app/auto_print.py
    |      Автоматическая печать и очистка Windows Print Queue
    |
    +-- app/label_print.py
    |      Ручные текстовые этикетки и PNG-изображения кодов
    |
    +-- app/resources/
    |      fonts.py       Загрузка шрифтов в память процесса
    |      backgrounds.py Подготовка и кеширование фонов
    |      __init__.py    Общий фасад и блокировки ресурсов
    |
    +-- app/utils.py
           Работа с принтерами и общие утилиты
    |
    v
Windows GDI / Print Spooler
    |
    v
Принтер
```

### Архитектурные принципы

1. **Единая точка входа.** `backend.py` регистрирует HTTP-маршруты, запускает фоновые мониторы и управляет временем жизни сервера.
2. **Разделение сценариев печати.** `auto_print.py` отвечает за автоматические задания, `label_print.py` — за ручную печать.
3. **Фоновый мониторинг.** Состояние выбранного принтера обновляется раз в секунду, список принтеров — раз в пять секунд. При поступлении автоматического задания состояние принтера дополнительно проверяется непосредственно.
4. **Синхронизация печати.** Общий `_print_lock` используется маршрутами автоматической и ручной печати. Одновременно выполняется только одна операция отправки этикетки в Windows spooler.
5. **Изоляция ресурсов.** Блокировки в `app/resources/` не позволяют очищать или заменять кеш шрифтов и фонов, пока они используются при печати.

### Назначение основных файлов

| Файл | Назначение |
| --- | --- |
| `backend.py` | HTTP API, история заданий, фоновые мониторы, блокировка печати и жизненный цикл сервера |
| `app/config.py` | Поиск, чтение и кеширование `config.json` |
| `app/auto_print.py` | Подготовка и автоматическая печать текстовых этикеток; вызов очистки очереди |
| `app/label_print.py` | Проверка ручного запроса, декодирование Base64 PNG и печать |
| `app/utils.py` | Получение списка принтеров, проверка состояния, очистка очереди и расчёт размеров |
| `app/resources/fonts.py` | Поиск, регистрация в памяти процесса и кеширование шрифтов |
| `app/resources/backgrounds.py` | Загрузка, подготовка и кеширование фоновых изображений |
| `app/resources/__init__.py` | Общая инициализация, освобождение ресурсов и контекст блокировки |

## Системные требования

- **ОС:** Windows 10 или Windows 11, 64-bit.
- **Python:** 3.10 или новее.
- **Оборудование:** принтер, установленный в Windows и имеющий совместимый драйвер GDI/WinSpool.

## Конфигурация

Backend читает общий файл конфигурации, который также использует десктопное приложение. Отдельного HTTP endpoint для изменения конфигурации нет.

### Расположение файла

1. В первую очередь используется `%APPDATA%\PrintNum\config.json`, если файл существует.
2. Если его нет, используется `config.json` в текущей рабочей директории процесса backend.

При изменении файла конфигурация перечитывается по изменению времени модификации и размера файла. Если новый файл временно невозможно прочитать, backend сохраняет последнюю успешно загруженную конфигурацию.

### Параметры

| Ключ | Тип | Использование |
| --- | --- | --- |
| `printer` | string | Точное имя принтера Windows |
| `paper` | string | Размер этикетки в миллиметрах, формат `Ширина*Высота`, например `30*20` |
| `excludedTexts` | array of strings | Подстроки, при совпадении с которыми автоматическая печать пропускается |
| `idNum` | boolean | Управляет отображением дополнительной части номера в автоматической этикетке |
| `endLine` | boolean | Включает подчёркивание основного текста в автоматической этикетке |
| `hybrid` | boolean | Включает гибридное форматирование автоматической этикетки |
| `expand` | number | Порог гибридного форматирования |
| `bold` | boolean | Жирное начертание основного текста автоматической этикетки |
| `font` | string | Имя файла шрифта без расширения для автоматической печати |
| `font_manual` | string | Имя файла шрифта без расширения для ручной текстовой печати |
| `background` | string | Имя файла фона без расширения для автоматической печати |
| `opacity` | number | Непрозрачность автоматического фона в процентах |
| `background_manual` | string | Имя файла фона без расширения для ручной текстовой печати |
| `opacity_manual` | number | Непрозрачность ручного фона в процентах |
| `themeStyle`, `theme` | string | Настройки интерфейса; модули печати backend их не используют |

Параметры шрифтов и фонов необязательны. Если ресурс не задан, не найден или не может быть загружен, для шрифта используется Arial, а этикетка печатается без фона.

### Пример конфигурации

```json
{
  "printer": "CHITENG-CT221B",
  "paper": "30*20",
  "excludedTexts": [
    "Прямой поток",
    "Расходники",
    "Возврат",
    "Продавцу",
    "Ozon Полка"
  ],
  "idNum": false,
  "endLine": false,
  "hybrid": true,
  "expand": 500,
  "bold": false,
  "font": "Arial",
  "font_manual": "Arial",
  "background": "auto-background",
  "opacity": 80,
  "background_manual": "manual-background",
  "opacity_manual": 90
}
```

### Правила исключений

Проверка `excludedTexts` применяется только к автоматическим маршрутам `/print-number` и `/ozon-shelf`.

- Сравнение выполняется по вхождению подстроки.
- Регистр не учитывается.
- Полного совпадения не требуется: текст `Ozon Полка - 1` совпадёт с правилом `Ozon Полка`.
- Совпавшее задание получает статус `excluded` и не отправляется на печать.
- Ручной маршрут `/print-label` эти правила не применяет.

## Ресурсы: шрифты и фоны

Ресурсы располагаются в пользовательской директории приложения:

- Шрифты: `%APPDATA%\PrintNum\fonts\`
- Фоны: `%APPDATA%\PrintNum\backgrounds\`

### Шрифты

- Поддерживаются файлы `.ttf` и `.otf`.
- В конфигурации указывается имя файла без расширения.
- Файл загружается только тогда, когда соответствующий тип печати запрашивает этот шрифт.
- Шрифт регистрируется через Windows `AddFontMemResourceEx` в памяти процесса. Он не устанавливается в систему и не добавляется в системный список шрифтов Windows.
- Загруженные шрифты кешируются; при смене настроенного файла старый ресурс освобождается, когда больше не используется.
- Если файл отсутствует, имя неоднозначно или загрузка завершилась ошибкой, используется Arial.

### Фоновые изображения

- В конфигурации указывается только имя файла без расширения. Backend самостоятельно ищет файл с таким именем в папке backgrounds.
- Поддерживаются изображения PNG, JPG, JPEG, BMP и WEBP. Поиск имени не зависит от регистра.
- Если файлы с одинаковым именем существуют в нескольких форматах, фон считается неоднозначным и не применяется.
- Фон подготавливается под фактический размер этикетки, с учётом заданной непрозрачности, и кешируется.
- Для автоматической и ручной текстовой печати используются независимые настройки фона.
- Фоны не применяются к графическим этикеткам barcode, QR и Data Matrix.
- Если файл отсутствует или не может быть обработан, печать продолжается без фона.

Backend читает файлы шрифтов и фонов; их добавление, переименование и удаление выполняются вне backend.

## Режимы запуска и управление процессом

### Стандартный режим

```powershell
python backend.py
```

Режим предназначен для запуска backend как дочернего процесса десктопного приложения. Если в течение 10 секунд не поступает HTTP-запросов, watchdog останавливает сервер.

### Автономный режим

```powershell
python backend.py --standalone
```

В этом режиме автоматическое завершение по бездействию отключено. Остановить процесс можно через `Ctrl+C` в консоли или средствами операционной системы.

При запуске backend инициализирует менеджеры ресурсов, получает начальное состояние принтера и список принтеров, затем запускает фоновые мониторы и HTTP-сервер.

## HTTP API

Базовый адрес: `http://127.0.0.1:5000`.

Для JSON-запросов используйте заголовок `Content-Type: application/json`. Автоматические маршруты читают JSON через безопасный режим Flask: если тело не является JSON-объектом или поле `text` отсутствует/пустое, запрос игнорируется с ответом `OK` (200).

### GET /

Проверка доступности backend.

- **Успех:** `200 OK`

Пример:

```json
{
  "status": true
}
```

### GET /printer-data

Возвращает единый снимок состояния backend. Маршрут читает RAM и не обращается напрямую к Windows API.

Поля:

- `listPrinters` — список принтеров, обновляемый фоновым монитором каждые 5 секунд.
- `printerOnline` — последнее состояние выбранного принтера, обновляемое монитором каждую секунду и непосредственной проверкой при автоматическом запросе.
- `printQueue` — история последних 100 автоматических текстовых заданий PrintNum, новые записи располагаются в начале.

Пример:

```json
{
  "listPrinters": ["CHITENG-CT221B", "XPrinter XP-365B"],
  "printerOnline": true,
  "printQueue": [
    {
      "status": "printed",
      "text": "500-1",
      "renameText": null,
      "receivedAt": "2026-11-14T15:30:00+03:00"
    }
  ]
}
```

Если история пуста, возвращается служебная карточка:

```json
{
  "status": "waiting",
  "text": null,
  "renameText": null,
  "receivedAt": null
}
```

Возможные статусы задания:

- `processing` — запрос принят и обрабатывается.
- `printed` — функция печати успешно завершила отправку задания в Windows spooler.
- `excluded` — автоматическое задание пропущено по правилу исключения.
- `printer_unavailable` — принтер недоступен при непосредственной проверке.
- `print_error` — при обработке или отправке задания произошла ошибка.

`waiting` используется только для пустой истории. `text` содержит исходный текст. `renameText` зарезервировано в структуре ответа и в текущей реализации остаётся `null`. `receivedAt` — время получения задания.

История относится только к автоматическим текстовым запросам. Ручные задания `/print-label` в неё не добавляются. История хранится в памяти и очищается при перезапуске backend.

### POST /print-number

Принимает текст для автоматической печати.

Запрос:

```json
{
  "text": "500-1"
}
```

Ответы и результат:

- Корректный запрос, успешная отправка или исключение по правилам — текстовый ответ `OK`, HTTP 200. Итоговый статус доступен через `GET /printer-data`.
- Некорректное JSON-тело, отсутствующий или пустой `text` — `OK`, HTTP 200; задание в историю не добавляется.
- Принтер недоступен — `OK`, HTTP 200; статус задания `printer_unavailable`.
- Ошибка обработки/печати — JSON `{"error":"Ошибка печати"}`, HTTP 500; статус задания `print_error`.

### POST /ozon-shelf

Принимает текст для автоматической печати этикетки полки Ozon.

Запрос:

```json
{
  "text": "Ozon Полка - 1"
}
```

Использует тот же обработчик, проверку доступности принтера, фильтрацию и механизм печати, что и `/print-number`. Специальное форматирование текста полки выполняется в модуле автоматической печати.

Ответы и статусы аналогичны `/print-number`.

### POST /print-label

Ручная печать этикетки. Этот маршрут не применяет `excludedTexts` и не добавляет задание в историю `printQueue`.

Поддерживаемые значения `contentType`:

- `text` — текстовая этикетка.
- `barcode` — PNG-изображение линейного штрихкода.
- `qr` — PNG-изображение QR-кода.
- `datamatrix` — PNG-изображение Data Matrix.

Пример текстовой этикетки:

```json
{
  "contentType": "text",
  "content": "Заказ № 12345",
  "bold": false,
  "underline": false,
  "showCodeText": false
}
```

Пример графической этикетки:

```json
{
  "contentType": "qr",
  "content": "Данные внутри QR",
  "codeImage": "iVBORw0KGgoAAAANSUhEUgAA...",
  "bold": false,
  "underline": false,
  "showCodeText": true
}
```

Для графических типов клиент передаёт готовое PNG-изображение в поле `codeImage` как Base64 без префикса `data:image/png;base64,`. Backend проверяет формат и размер изображения, декодирует его и отправляет на печать. Поле `content` содержит исходное значение и может использоваться как подпись под кодом, если `showCodeText` равно `true`.

Общие ограничения:

- `content` — непустая строка длиной не более 4096 символов.
- `codeImage` для графических типов — PNG не более 4 МБ после декодирования.
- `bold`, `underline`, `showCodeText` должны быть boolean.

Ответы:

- Успешная отправка: `{"status":true}`, HTTP 200.
- Некорректный запрос: JSON с полем `error`, HTTP 400.
- Принтер недоступен по состоянию фонового монитора: JSON с полем `error`, HTTP 503.
- Ошибка печати: JSON с полем `error`, HTTP 500.

Ручная печать использует тот же `_print_lock`, что и автоматическая, но не очищает Windows Print Queue перед отправкой.

### POST /shutdown

Запрашивает штатную остановку backend. Маршрут предназначен для локального клиента приложения.

Для успешного запроса необходимы одновременно:

- подключение с loopback-адреса `127.0.0.1` или `::1`;
- заголовок `X-PrintNum-Shutdown: local-client`.

Успешный ответ — JSON `{"status":true,"message":"Запрошена остановка сервера"}`, HTTP 200. При отсутствии условий доступа возвращается HTTP 403.

## Обработка заданий и конкурентность

### Автоматическая печать

Для валидного автоматического запроса backend:

1. Добавляет запись в историю со статусом `processing`.
2. Непосредственно проверяет доступность выбранного в конфигурации принтера.
3. Если принтер недоступен, устанавливает `printer_unavailable` и завершает обработку.
4. Получает общую блокировку печати `_print_lock`.
5. Проверяет правила `excludedTexts` в модуле печати.
6. Перед подготовкой этикетки пытается очистить Windows Print Queue выбранного принтера.
7. Подготавливает текст, применяет настроенный шрифт и фон, затем отправляет задание через GDI.
8. Устанавливает итоговый статус `printed`, `excluded` или `print_error`.

### Очистка Windows Print Queue

Перед каждым автоматическим заданием вызывается `clear_printer_queue(printer_name)`. Функция получает имя принтера из уже загруженной конфигурации и пытается удалить задания из очереди именно этого принтера.

Очистка относится к системной очереди Windows выбранного принтера, а не только к заданиям PrintNum. Поэтому в ней могут находиться и задания других приложений.

Ошибки очистки не прерывают автоматическую печать:

- ошибка открытия принтера или получения списка заданий журналируется; печать продолжается без успешной очистки;
- ошибка удаления отдельного задания журналируется, после чего функция пытается удалить следующие задания;
- ошибка закрытия дескриптора также журналируется и не отменяет отправку этикетки.

Это означает, что при ошибке очистки старые задания могут остаться в Windows Print Queue. Backend всё равно продолжит попытку отправить новое задание. Сам маршрут ручной печати `/print-label` очередь не очищает.

### Конкурентность

- Маршруты `/print-number`, `/ozon-shelf` и `/print-label` используют общую блокировку `_print_lock`.
- Одновременно выполняется только одна операция печати внутри backend. Остальные запросы ожидают освобождения блокировки в потоках Flask.
- Очистка Windows Print Queue выполняется внутри критической секции автоматической печати.
- После успешного вызова `EndDoc` задание передано Windows Print Spooler; дальнейшая физическая печать контролируется Windows и драйвером принтера.
- История `printQueue` хранится только в оперативной памяти процесса. Она не является персистентной очередью сообщений и очищается при перезапуске backend.

### Фоновые мониторы

- Состояние выбранного принтера обновляется раз в секунду.
- Список доступных принтеров обновляется раз в пять секунд.
- Если обновление списка принтеров завершается ошибкой, сохраняется последнее успешное значение.
- Ошибка отдельной итерации монитора не останавливает его работу.
- Автоматические запросы выполняют дополнительную непосредственную проверку принтера и не полагаются только на кеш монитора.

## Диагностика и устранение неполадок

1. **Backend не отвечает.** Выполните `GET http://127.0.0.1:5000/`. Если ответа нет, проверьте, запущен ли процесс, свободен ли порт 5000 и доступен ли loopback-интерфейс.
2. **Неверное имя принтера.** Сравните `printer` в конфигурации со значениями `listPrinters` из `GET /printer-data`. Имя должно совпадать с системным именем принтера.
3. **Принтер недоступен.** Проверьте `printerOnline`, питание, кабель или сеть, состояние устройства и режим «Работать автономно» в Windows.
4. **Задание имеет статус `excluded`.** Проверьте `excludedTexts`: достаточно вхождения любой непустой строки правила без учёта регистра.
5. **Задание имеет статус `print_error`.** Изучите журнал backend. Ошибка может возникать при открытии принтера, создании GDI-контекста, подготовке этикетки или отправке задания.
6. **Очередь Windows не очистилась.** Найдите в журнале сообщения об ошибках очистки. Такая ошибка не отменяет попытку печати; оставшиеся задания могут повлиять на фактический порядок вывода.
7. **Графическая этикетка не проходит проверку.** Убедитесь, что `codeImage` содержит чистый Base64 PNG без URI-префикса, а размер декодированных данных не превышает 4 МБ.
8. **Шрифт не применяется.** Проверьте, что файл `.ttf` или `.otf` находится в `%APPDATA%\PrintNum\fonts\`, а в конфигурации указано имя файла без расширения. При проблеме загрузки используется Arial.
9. **Фон не применяется.** Проверьте наличие файла в `%APPDATA%\PrintNum\backgrounds\`, правильность имени с расширением и параметры opacity. При ошибке фон пропускается.
10. **Одновременные запросы ожидают печати.** Это ожидаемое поведение общей блокировки `_print_lock`: отправка заданий в backend сериализована. Физическое выполнение после передачи задания зависит от Windows Print Spooler и драйвера.
