# PrintNum Backend

Локальный HTTP-сервис для автоматизированной и ручной печати этикеток в Windows. Backend самостоятельно отслеживает состояние принтера, принимает тексты, обрабатывает их и хранит историю результатов. Frontend получает данные о принтере одним запросом.

## Возможности

- Фоновая проверка доступности выбранного принтера каждую секунду.
- Обновление списка установленных принтеров каждые 5 секунд.
- Непосредственная проверка выбранного принтера при поступлении каждого текста.
- История последних 100 текстовых заданий со статусами обработки.
- Печать номеров, полок Ozon, текста и графических кодов.
- Последовательная отправка заданий на принтер через `_print_lock`.
- Автоматическое завершение процесса после 10 секунд простоя в обычном режиме.

## Архитектура

```text
backend.py
  ├── GET /printer-data
  ├── POST /print-number
  ├── POST /ozon-shelf
  ├── POST /print-label
  ├── printer_status_monitor (1 сек.)
  ├── printer_list_monitor (5 сек.)
  └── app/
      ├── auto_print.py
      ├── config.py
      ├── label_print.py
      ├── resources.py
      └── utils.py
```

Мониторы работают независимо от frontend и запросов на печать. `GET /printer-data` только читает подготовленное состояние из оперативной памяти и не вызывает Windows API.

## Запуск

Требуется Windows 10/11 и Python 3.10+.

```powershell
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
python backend.py
```

Автономный режим без автоматического завершения по простою:

```powershell
python backend.py --standalone
```

Оба фоновых монитора работают в обоих режимах. Остановка через `POST /shutdown` доступна только локальному клиенту с заголовком `X-PrintNum-Shutdown: local-client`.

## Конфигурация

Backend читает `config.json` в режиме Read-Only. Сначала используется `%APPDATA%\\PrintNum\\config.json`, затем локальный `config.json`.

Основные параметры:

| Ключ | Назначение |
|---|---|
| `printer` | Точное имя выбранного Windows-принтера |
| `paper` | Размер этикетки в мм, например `30*20` |
| `excludedTexts` | Подстроки, при совпадении с которыми автопечать пропускается |
| `font` | Выбранный шрифт |
| `idNum`, `endLine`, `hybrid`, `expand`, `bold` | Настройки форматирования автопечати |

## HTTP API

Базовый адрес: `http://127.0.0.1:5000`.

### GET /

Проверка доступности сервера.

Ответ:

```json
{ "status": true }
```

### GET /printer-data

Возвращает единый снимок состояния backend:

- `listPrinters` — список доступных Windows-принтеров.
- `printerOnline` — последнее состояние выбранного принтера, обновляемое фоновым монитором и непосредственными проверками при поступлении текстов.
- `printQueue` — последние 100 текстовых заданий, новые находятся в начале списка.

Пример:

```json
{
  "listPrinters": ["CHITENG-CT221B", "XPrinter XP-365B"],
  "printerOnline": true,
  "printQueue": [
    {
      "status": "printed",
      "text": "500-1",
      "renameText": null,
      "receivedAt": "2026-11-14T15:30:00+03:00"
    },
    {
      "status": "processing",
      "text": "500-2",
      "renameText": null,
      "receivedAt": "2026-11-14T15:30:05+03:00"
    }
  ]
}
```

Если заданий ещё не было, `printQueue` содержит одну служебную карточку ожидания:

```json
{
  "status": "waiting",
  "text": null,
  "renameText": null,
  "receivedAt": null
}
```

Статусы задания:

| Статус | Значение |
|---|---|
| `processing` | Текст принят и обрабатывается |
| `excluded` | Текст совпал с правилом исключения |
| `printer_unavailable` | Принтер недоступен при проверке перед обработкой |
| `printed` | Задание успешно отправлено на печать |
| `print_error` | Во время печати произошла ошибка |
| `waiting` | История заданий пуста; служебная карточка для UI |

Поле `text` сохраняет исходный текст, `renameText` предназначено для результата переименования и пока равно `null`, если переименование не выполнялось. `receivedAt` фиксируется при приёме и не меняется при обновлении статуса.

### POST /print-number и POST /ozon-shelf

Оба маршрута принимают JSON:

```json
{ "text": "500-1" }
```

Порядок обработки:

1. Регистрация задания со статусом `processing`.
2. Непосредственная проверка выбранного принтера через `status_printer()`. Результат фонового кеша для этого решения не используется.
3. Если принтер недоступен — статус `printer_unavailable`, обработка завершается.
4. Проверка `excludedTexts`; при совпадении статус становится `excluded`.
5. Отправка на печать под `_print_lock`.
6. Результат — `printed` или `print_error`.

Оба маршрута сохраняют прежний HTTP-ответ для совместимости с отправителями: `OK` при обработанном запросе и JSON с HTTP 500 при ошибке печати.

### POST /print-label

Ручная печать этикетки. Поддерживает `text`, `barcode`, `qr` и `datamatrix`. Для графических кодов передаётся PNG в Base64 в поле `codeImage`.

### POST /shutdown

Локальная штатная остановка backend. Требует заголовок `X-PrintNum-Shutdown: local-client`.

Старые маршруты `GET /status-printer` и `GET /listPrinters` удалены. Для получения обоих значений используется `GET /printer-data`.

## Конкурентность и отказоустойчивость

- `_state_lock` защищает общее состояние и время активности.
- `_print_lock` сериализует операции печати и не используется мониторами.
- Ошибка получения списка принтеров сохраняет последнее успешное значение.
- Ошибка проверки статуса не завершает монитор; состояние отмечается как недоступное.
- Ошибка одного задания не изменяет статусы других.
- Внутренняя `printQueue` — история заданий PrintNum, не Windows Print Queue.
- `clear_printer_queue()` и его использование в автоматической печати не изменены.
- При остановке backend оба фоновых потока получают сигнал завершения и ожидаемо останавливаются до освобождения ресурсов.
