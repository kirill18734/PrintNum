# Backend PrintNum

Backend — локальный HTTP-сервис приложения PrintNum. Он получает задания
автопечати от браузерного расширения и команды печати этикеток от интерфейса
Tauri, проверяет настройки и отправляет задания в подсистему печати Windows.

## Архитектура

Backend организован как модульный монолит на Flask:

```text
HTTP-запрос
    ↓
API-маршрут (app/api)
    ↓
Сервис приложения (app/services)
    ├── Правила и проверка данных (app/domain)
    ├── Репозиторий настроек (app/infrastructure/config_repository.py)
    └── Адаптер принтера Windows (app/infrastructure)
```

- **API-маршруты** разбирают HTTP-запросы, вызывают сервисы и формируют
  HTTP-ответы.
- **Сервисы** координируют сценарии автопечати, ручной печати и доступа к
  принтеру.
- **Доменный слой** содержит независимые от Flask и Windows правила
  форматирования, проверки запросов и поиска исключений.
- **Инфраструктурный слой** читает конфигурацию и взаимодействует с Windows
  Print Spooler, GDI и Pillow.
- Зависимости передаются приложению при создании через `create_app`. Поэтому
  маршруты и сценарии можно тестировать с подменным принтером, не имея
  физического устройства и библиотек Windows.

## Структура каталогов

```text
backend/
  app/
    api/              HTTP-маршруты: состояние, принтеры, автопечать, этикетки
    domain/           Проверка запросов, правила исключения и макет этикетки
    infrastructure/   Настройки, жизненный цикл и адаптеры Windows
    services/         Сценарии печати и координация доступа к принтеру
    factory.py        Создание Flask-приложения и подключение маршрутов
  backend.py          Точка входа для запуска сервера
  test_*.py           Модульные и интеграционные тесты
  requirements.txt    Зависимости Python
```

Отрисовка и отправка заданий через GDI находятся в
`app/infrastructure/windows_rendering.py`. Низкоуровневые вызовы Windows
принтера находятся в `app/infrastructure/windows_printer.py`.

## Требования

- Windows — для фактической работы с принтерами.
- Python 3 и зависимости из `requirements.txt`.
- Установленный и настроенный принтер Windows для выполнения печати.

Установка зависимостей из корня репозитория:

```powershell
python -m pip install -r backend/requirements.txt
```

Пакет `pywin32` и модуль `Pillow.ImageWin` предназначены для Windows. Создание
Flask-приложения и большинство HTTP-тестов можно выполнять в другой ОС с
установленными Flask-зависимостями и тестовым адаптером принтера, но реальная
печать там недоступна.

## Настройки приложения

В Windows настройки читаются из общего с настольным приложением файла:

```text
%APPDATA%\PrintNum\config.json
```

Если переменная окружения `APPDATA` отсутствует, используется каталог
`backend/PrintNum` рядом с исходниками. Файл создаёт и обновляет приложение;
backend читает его и не сохраняет в него изменения. Данные кешируются по времени
изменения файла, а при чтении возвращается копия настроек.

Используемые ключи:

| Ключ | Назначение |
| --- | --- |
| `printer` | Имя выбранного принтера Windows |
| `running` | Разрешена ли автопечать |
| `excludedTexts` | Фразы, при наличии которых задание автопечати пропускается |
| `paper` | Размер этикетки в миллиметрах в формате `ширина*высота`, например `30*20` |
| `idNum` | Показывать дополнительную часть номера |
| `endLine` | Использовать подчёркивание вместо завершающей точки |
| `hybrid` | Включить гибридное форматирование номера |
| `expand` | Порог гибридного форматирования |

Настройки темы и пользовательского интерфейса backend не использует.

## Запуск

Из корня репозитория:

```powershell
python backend/backend.py
```

Либо из каталога `backend`:

```powershell
python backend.py
```

Сервер слушает только локальный адрес `127.0.0.1:5000`. Если backend не получает
запросов 10 секунд, он штатно завершает HTTP-сервер. Таймаут можно изменить при
программном запуске `run_server(idle_timeout=...)`.

При запуске через Tauri backend запускается скрытым процессом. Tauri сначала
проверяет `GET /`; если backend уже отвечает, второй экземпляр не стартует.
Остановка отправляет локальный `POST /shutdown`.

## HTTP API

Все маршруты используют адрес `http://127.0.0.1:5000`. Для JSON-запросов
передавайте заголовок `Content-Type: application/json`.

### `GET /`

Проверка доступности backend. Используется Tauri перед запуском нового процесса.

Ответ `200`:

```json
{"status": true}
```

### `GET /listPrinters`

Возвращает имена локальных и подключённых принтеров Windows.

Ответ `200`:

```json
{"listPrinters": ["Имя принтера"]}
```

При ошибке перечисления устройств возвращается `500` с JSON-полем `error`.

### `GET /status-printer`

Проверяет выбранный в настройках принтер. Если принтер не выбран или Windows
сообщает о критической ошибке, `printerOnline` будет `false`.

Ответ `200`:

```json
{"printerOnline": true}
```

### `POST /print-number`

Принимает номер или текст для автоматической печати:

```json
{"text": "500-1"}
```

- Некорректный запрос: `400` и JSON-поле `error`.
- Если автопечать выключена, текст пустой или принтер недоступен, запрос
  игнорируется; ответ — `200 OK`.
- Если текст совпадает с правилом из `excludedTexts`, задание пропускается.
  Печать не выполняется, уведомление в интерфейсе не показывается. Backend
  возвращает `200` с информацией о сработавшем правиле:

  ```json
  {"status": "skipped", "rule": "Прямой поток"}
  ```

- Если задание отправлено на печать, ответ — `200 OK`.
- Если отправка задания завершилась ошибкой, ответ — `500` и JSON-поле `error`.

Форматирование номера зависит от `idNum`, `endLine`, `hybrid` и `expand`.
Список правил проверяется без учёта регистра.

### `POST /print-label`

Принимает команду ручной печати этикетки:

```json
{
  "contentType": "text",
  "content": "Заказ № 12345",
  "bold": false,
  "underline": false,
  "showCodeText": false
}
```

Допустимые значения `contentType`: `text`, `barcode`, `qr`, `datamatrix`.
Для типов, отличных от `text`, дополнительно требуется `codeImage` — строка
Base64 с данными PNG. Обычно frontend генерирует кодовое изображение до отправки
запроса. Размер декодированного изображения — не более 4 МБ. Текст `content`
должен быть непустым и не длиннее 4096 символов; параметры `bold`, `underline`
и `showCodeText` должны быть логическими значениями.

Успешный ответ `200`:

```json
{"status": "printed"}
```

Возможные ошибки:

| HTTP | Причина |
| --- | --- |
| `400` | Некорректные данные запроса, тип содержимого или изображение |
| `409` | В настройках не выбран принтер |
| `413` | Размер HTTP-запроса превышает установленный лимит 6 МБ |
| `503` | Выбранный принтер не готов к печати |
| `500` | Ошибка Windows-драйвера или отправки задания |

### `POST /shutdown`

Запрашивает штатную остановку процесса. Маршрут предназначен для локального
управления приложением Tauri и принимает запрос только с loopback-интерфейса.
Также требуется заголовок:

```text
X-PrintNum-Shutdown: local-client
```

Если передан заголовок `Origin`, он должен соответствовать одному из разрешённых
адресов интерфейса Tauri или Vite dev-сервера.

Принятый запрос получает ответ `202`:

```json
{"status": "shutting-down"}
```

Неподходящий источник или отсутствие маркера дают `403`.

## Жизненный цикл

`backend.py` создаёт Flask-приложение, запускает встроенный сервер Werkzeug в
потоковом режиме и отдельный наблюдатель активности. Каждый запрос обновляет
время последней активности; незавершённые запросы учитываются, поэтому сервер
не останавливается посреди обработки. По таймауту простоя или запросу
`/shutdown` вызывается штатная остановка сервера и закрытие сокета. Процесс не
завершается принудительным `os._exit`.

Печать сериализована в `PrinterService`: перед каждым заданием автопечати или
ручной печати backend перечисляет очередь выбранного принтера и удаляет только
задания, имя документа которых начинается с `PrintNum:`. При отправке новых
заданий backend выставляет эту метку через имя документа GDI. Задания других
приложений в той же очереди остаются нетронутыми. Очистка ограничена принтером,
указанным в текущем `config.json`; очереди остальных принтеров не просматриваются.


## Тестирование

Запустить тесты из корня репозитория:

```powershell
python -m unittest discover -s backend -v
```

Тесты проверяют:

- правила исключения и валидацию данных;
- ответы API и маршруты принтеров;
- автопечать, ручную печать и ошибки принтера;
- декодирование PNG для этикеток с кодами;
- штатную остановку по таймауту и через HTTP-маршрут.

Интеграционные тесты используют `FakePrinter`, поэтому задания на реальный
принтер не отправляются.

## Сборка для Tauri

Конфигурация упаковки находится в `src-tauri/tauri.conf.json`: при сборке
Tauri ожидает готовый файл `backend/output/backend.exe` и включает его в ресурсы
приложения как `backend.exe`. Tauri запускает этот исполняемый файл скрыто;
команды запуска и штатной остановки описаны в
`src-tauri/capabilities/default.json`.

Точка входа backend — `backend/backend.py`. После изменения backend необходимо
пересобрать `backend.exe`, чтобы приложение Tauri содержало актуальную версию.
